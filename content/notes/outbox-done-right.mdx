An agent that cannot deliver an event reliably is not deployable, no matter how small the binary. The deployment problem behind DragonScale has an unglamorous half: durable side effects across crashes and restarts, without dragging in heavyweight infrastructure.

Working-note speculation: the transactional outbox — writing the event to SQL in the same transaction as the state change, then relaying it via NATS — looks like the right shape of answer. No ceremony beyond a table and a relay, which fits the small-runtime thesis rather than fighting it.

Open and unverified: whether the relay should be at-least-once with idempotent consumers or chase exactly-once, and where the outbox table lives when the runtime itself is backed by libSQL. This stays a note, not a report, until the date, URL, and benchmarks are verified.
