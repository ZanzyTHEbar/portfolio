## Strange Idea

One builder pairs project error codes with structured details.

## Hypothesis

Across Go projects, `Builder`, gRPC-inspired codes, `ErrMap`, and structured details define error shapes for direct and deferred flows.

## Constraints

- Use across Go projects
- Code meanings must not vary by call site
- Deferred and multi-error flows must fit the same shape

## System

errbuilder-go is a Go error-builder library. Its `Builder` constructs errors with a message, code, and details. `ErrMap` collects errors across complex or deferred flows. Five builtin wrappers demonstrate common usage.

## Reality

The open-source Go module originated in the author's projects. It pairs with assert-lib.

## Open Questions

- README installation and usage snippets use `errorbuilder` and `errsx` import paths that do not match the module name; the canonical import path needs confirmation.
- Use cases requiring project-specific additions to the five builtin wrappers need identification.
- `ErrMap` needs testing for deferred and multi-error flows.
