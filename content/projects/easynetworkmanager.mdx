## Strange Idea

What if connecting an ESP32 to WiFi, exposing a REST API, pushing OTA updates, and streaming telemetry were one declarative library instead of five wiring jobs?

## Hypothesis

If an embedded framework owns the full lifecycle — connection, provisioning, API surface, and updates — behind a single configuration call, then device firmware turns into application logic instead of networking plumbing.

## Constraints

- microcontroller memory and flash budgets (ESP32/ESP8266, M5Stack)
- captive-portal provisioning on-device
- resilient reconnects without user intervention

## System

Every ESP32 project re-solves the same stack: WiFi provisioning, mDNS, REST, WebSockets, OTA, MQTT, and state in between. EasyNetworkManager is a C++17 IoT framework for ESP32/ESP8266/M5Stack that collapses all of it behind one initialization call — a WiFiManager-based web portal with AP fallback, mDNS discovery, Async OTA updates, REST and WebSocket servers, MQTT publishing, and persistent configuration with state management across dedicated handler classes.

## Reality

In the PlatformIO registry as a versioned library with example sketches, docs site, and GPL-3.0 license; in production use inside OpenIris-era deployments, with ESP32-C3 support in development.

## Decisions

- C++17 throughout, accepting the toolchain requirement for modern language features.
- PlatformIO-first distribution so the library installs like any other dependency.

## Open Questions

- `POST` JSON handling is still in development in the README — what breaks until it lands?
- ESP8266 support is beta with manual dependency installs; ESP32-C3 is untested — do both converge or does one get cut?
- Docs site is being built — does it replace the examples folder as the onboarding path?
