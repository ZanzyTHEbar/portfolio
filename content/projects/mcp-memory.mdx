## Strange Idea

Can persistent semantic memory be useful without becoming its own infrastructure project?

## Hypothesis

If the memory server is a single Go binary on libSQL, then it beats the TS original on speed and footprint.

## Constraints

- memory footprint
- zero runtime deps
- multi-project isolation

## System

Agent memory usually grows into its own infrastructure project. The bet here is a single Go binary on libSQL — vector plus hybrid search, knowledge graphs, multi-project isolation, and metrics.

## Reality

Author-reported 2× performance and 40% lower memory versus the TypeScript original.

## Open Questions

- Benchmark methodology is unmeasured here; the 2×/40% figures await a reproducible harness.
- Which workloads? Ingest vs recall vs hybrid?
