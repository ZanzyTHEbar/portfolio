## Strange Idea

Persistent agent memory runs from a single Go binary backed by libSQL.

## Hypothesis

Under equivalent ingest, recall, and hybrid-search workloads, does the Go/libSQL implementation complete operations faster and use less memory than the TypeScript original?

## Constraints

- memory footprint
- zero runtime deps
- multi-project isolation

## System

MCP Memory is a single Go binary on libSQL with vector and hybrid search, knowledge graphs, multi-project isolation, and metrics.

## Reality

The repository claims 2× performance and 40% lower memory than the TypeScript original. Both figures remain unverified.

## Open Questions

- The repository contains database benchmark tests, but no comparative harness supporting the 2x and 40% claims.
- Comparative results for ingest, recall, and hybrid search are not documented.
