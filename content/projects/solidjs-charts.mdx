## Strange Idea

What if Chart.js felt native inside SolidJS reactivity?

## Hypothesis

If chart bindings follow Solid's fine-grained reactivity, then dashboards update without framework ceremony or wasted re-renders.

## Constraints

- bundle size (tree-shaking matters)
- Chart.js registration ceremony (controllers, elements, scales, plugins)
- Solid reactivity semantics (no virtual-DOM assumptions)

## System

Dashboards usually pay a framework tax: wrapper components that re-render whole charts on every tick. This is a SolidJS wrapper around Chart.js — chart-type components over explicitly registered Chart.js pieces, with a tree-shakable import path so applications only bundle the controllers and scales they use.

## Reality

Published npm package with versioned releases, a demo site, and usage docs. The repo under the author's account is a maintained fork; what it carries beyond upstream is unstated here.
