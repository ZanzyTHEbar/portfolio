## Strange Idea

Each application fault carries a stable fault code and a transport code.

## Hypothesis

Across process boundaries, wrapped Go faults expose a stable application code alongside its mapped transport code for inspection.

## Constraints

- stdlib compatibility (`errors.Is` / `errors.As` must keep working)
- context cancellation and deadline semantics
- Process-wide code mappings and their global state

## System

faults-go is a Go library for structured application faults. `New` and `Wrap` create and wrap faults with normalized key/value details. `CodeOf` and `IsCode` inspect codes. Project-specific codes can be registered process-wide during startup. The library builds on errbuilder-go for transport-aware error values and integrates assert-lib reporting.

## Decisions

- Durable application codes and transport codes remain separate.
- The library builds on errbuilder-go and assert-lib.
