## Strange Idea

A Go binary can combine a narrow agent runtime with explicit trust boundaries.

## Hypothesis

In ZanzyTHEbar/dragonscale, SecureBus documents tool capability declarations, secret injection, and output scanning around the in-process main runtime; network and filesystem enforcement remain follow-on work for the Isolated Tool Runtime.

## Constraints

- Tools declare capabilities to SecureBus.
- SecureBus injects secrets and scans tool output.
- The main runtime executes in process.
- Network and filesystem enforcement remain follow-on isolation work.
- Current MCP support is not documented.

## System

ZanzyTHEbar/dragonscale is a fork of sipeed/picoclaw. It is a compact Go single binary with persistent memory, DAG execution, SecureBus, and an Isolated Tool Runtime. SecureBus documents tool capability declaration, secret injection, and output scanning. The main runtime executes in process, while network and filesystem enforcement are follow-on work. Current MCP support is not documented.

## Reality

Public documentation describes SecureBus and the Isolated Tool Runtime. Current MCP support is not documented.

## Open Questions

- No public benchmark or evaluation figure is documented.
- Daemon and WASM isolation remain follow-on work for network and filesystem enforcement.
- Whether libSQL backs an outbox table and what role it serves still need definition.
