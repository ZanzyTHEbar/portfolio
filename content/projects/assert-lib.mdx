## Strange Idea

assert-lib logs and continues by default. Crash on failure requires opt-in.

## Hypothesis

Given a failed assertion, default mode logs and continues; silent mode suppresses logs; debug and verbose modes add stack traces; crash-on-failure terminates only when opted in.

## Constraints

- Production paths use crash-on-failure only when opted in
- Structured logging with flush controls
- Silent checks suppress logging in selected paths

## System

assert-lib is a Go assertion library that logs and continues by default. It uses package-level functions, so no instance is required. Function Options compose behavior. The library provides JSON and text formatters, crash-on-failure opt-in, silent mode, debug and verbose stack-trace modes, and testing and production presets.

## Reality

The open-source Go module has Go Reference documentation and examples. It was authored for systems use.

## Decisions

- Crashing requires explicit opt-in.
- Function Options compose behavior.

## Open Questions

- Deferred and batched assertions need behavior testing.
- The README lists Text, JSON, and YAML formatters; YAML's API status needs a decision.
- The relationship between package-level functions and instance handlers needs a long-term API decision.
