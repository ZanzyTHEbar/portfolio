## Strange Idea

An assertion library can log and continue by default, with explicit crash opt-in.

## Hypothesis

Safe-by-default assertions with crash, silent, debug, and verbose modes can support systems and real-time paths where a panic would be worse than the bug.

## Constraints

- no crashing in production paths unless opted in
- structured logging with flush controls
- performance-critical sections need silent checks

## System

assert-lib is a lightweight Go assertion library that logs and continues by default. It uses package-level functions, so no instance is required. Function Options compose behavior. The library provides JSON or text formatters, crash-on-failure opt-in, silent mode, debug and verbose stack-trace modes, and testing and production presets.

## Reality

The open-source Go module has Go Reference docs and examples. It was authored for systems and real-time use.

## Decisions

- Crashing requires explicit opt-in.
- Function Options compose behavior.

## Open Questions

- Do deferred/batched assertions hold up in real-time paths, or does per-assertion checking win where latency matters?
- README lists Text, JSON, and YAML formatters. Does YAML earn its keep, or does the surface shrink to JSON + text?
- Package-level functions vs. instance handlers: does one usage win, or do both stay?
